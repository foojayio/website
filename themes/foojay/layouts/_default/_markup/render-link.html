{{- /* Link render hook. Four jobs: 1. Absolute foojay.io links in migrated content (e.g. "See also" links) point at the live WordPress site -- rewrite them to this site's path. 2. Root-relative internal links get the baseURL subpath (relURL only prefixes it when the path doesn't already start with "/"). 3. Links to any other host are external -> open in a new tab. 4. A bare filename that matches a page-bundle resource -> that resource. String checks (not urls.Parse, which errors on malformed migrated URLs). htmlUnescape on .Destination/.Title is what goldmark's own link renderer does before emitting, and taking over rendering here means taking that over too. CommonMark decodes entity references in link destinations, so migrated WordPress hrefs holding `?a=1&b=2` are CORRECT Markdown for `?a=1&b=2`. Without this the raw `&` reaches the href and html/template escapes it a second time to `&amp;`, i.e. the browser requests a query param literally named `amp;b`. ~90 posts carry such links. Same failure mode as the codeblock hook -- see render-codeblock.html. */ -}} {{- $orig := .Destination | htmlUnescape -}} {{- $dest := $orig -}} {{- $isAbs := or (hasPrefix $orig "http://") (hasPrefix $orig "https://") (hasPrefix $orig "//") -}} {{- /* Host-anchored so foojay.social and query strings don't false-match. */ -}} {{- $internal := or (hasPrefix $orig "https://foojay.io") (hasPrefix $orig "http://foojay.io") (hasPrefix $orig "https://www.foojay.io") (hasPrefix $orig "http://www.foojay.io") (hasPrefix $orig "//foojay.io") -}} {{- $external := and $isAbs (not $internal) -}} {{- if $internal -}} {{- $dest = replaceRE "^(https?:)?//(www\\.)?foojay\\.io" "" $dest -}} {{- end -}} {{- if not (or $external (hasPrefix $dest "http") (hasPrefix $dest "//") (hasPrefix $dest "mailto:") (hasPrefix $dest "#") (hasPrefix $dest "data:")) -}} {{- /* 4. A bare filename co-located with index.md -> that page-bundle resource, the same lookup render-image.html does. Without it a link to a file in the author's own folder -- a PDF, a video, a zip -- fell through to relURL and resolved against the SITE ROOT (/website/handout.pdf) while Hugo published the file inside the bundle (/website/today//handout.pdf), so the link 404'd and nothing said so. An image already worked, which is exactly why this went unnoticed: ![](shot.png) resolves and [pdf](handout.pdf) does not. Only a destination that actually matches a resource is rewritten; everything else (/today/..., ../foo/) falls through to the relURL branch untouched. */ -}} {{- $res := false -}} {{- with .Page }}{{ $res = .Resources.GetMatch $dest }}{{ end -}} {{- with $res -}} {{- $dest = .RelPermalink -}} {{- else -}} {{- $dest = $dest | strings.TrimPrefix "/" | relURL -}} {{- end -}} {{- end -}} {{ .Text | safeHTML }}
