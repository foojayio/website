{{- /* The single definition of "how does this page paginate", returning the current pager or false. It exists because of an ordering trap: baseof.html needs the pager in to write a self-referencing canonical on /today/page/2/, and renders BEFORE `{{ block "main" }}`. Hugo allows .Paginate any number of times but ERRORS IF THE ARGUMENTS DIFFER between calls, so a bare .Paginator in the head collides with posts/list.html's. Routing both through one partial makes the arguments identical by construction. Deliberately plain `partial`, NOT `partialCached`: Hugo renders /today/, /today/page/2/ … by re-executing the same Page with the pager advanced, so a cache keyed on the page hands page 2 the page-1 pager. ONE return, at the end. Hugo rejects a partial with a `return` that other statements fall through past. */ -}} {{- $pager := false -}} {{- if eq .Kind "term" -}} {{/* Category term pages paginate .Pages, which is what .Paginator does. */}} {{- $pager = .Paginator -}} {{- end -}} {{- if and (eq .Kind "section") (eq .Section "posts") -}} {{/* Posts are bucketed into /// subdirectories, so .Pages (direct children) would only see the year sub-sections. Paginate all posts recursively, newest first. */}} {{- $pager = .Paginate .RegularPagesRecursive.ByDate.Reverse -}} {{- end -}} {{/* An author or sponsor profile paginates a list that is NOT its own children -- the posts live in content/posts/ and are attributed by slug. Keyed on `type`, not on Kind alone: the parent listings /today/author/ and /our-sponsors/ are sections in the same section and must NOT paginate posts. Both are branch bundles purely because .Paginate refuses a page kind. */}} {{- if eq .Type "author" -}} {{- $pager = .Paginate (partial "author-posts.html" .) -}} {{- end -}} {{- if eq .Type "sponsor" -}} {{- $pager = .Paginate (partial "sponsor-posts.html" .) -}} {{- end -}} {{- return $pager -}}
