{{/* Renders a post's author byline. Posts can have multiple authors (`authors:` list); falls back to the legacy single `author:` slug so not-yet-reconverted posts still show a byline. Called either with the Page -- the normal case -- or with a dict: page the Page (required) maxNames above this many authors, render "N authors" instead of the names (0, the default, always names everyone) pagefindMeta stamp data-pagefind-meta="author" on the wrapper, so the names become the "author" meta key of this page's search result (see below) avatars show each author's face before their name (default false). Above ONE author this becomes a row of overlapping faces plus a count instead -- see the $pile branch. `maxNames 1` is what the related-posts cards pass. A podcast episode can credit a dozen people -- foojay-podcast-94 credits twelve -- and in a ~178px card that byline is taller than the thumbnail above it and buries the title and date, which are what a reader actually picks the next article on. It is a count rather than a truncated list ("Frank Delporte and 11 others") because at this size the first name is not more meaningful than the rest, it is just the one that sorted first. The collapsed form is a , not a link: there is no single author page to send twelve people to, and the card's title link already goes to the post that names them. THE .byline-group WRAPPER IS LOAD-BEARING, and it belongs here rather than in each caller. Every place a byline appears is a flex row with a `gap` (.post-meta, .post-card-meta), and a flex container makes EVERY child its own item -- so without the wrapper the names and the ", " between them were separate items and the gap was applied around the comma too, rendering "Dominika Tasarz , Luqman Saeed". Wrapped, the flex row sees one item and the names and commas inside it flow as ordinary inline text. posts/single.html used to add this wrapper itself, which is exactly why the post header looked right and the cards did not. `avatars` PUTS THE FACE INSIDE THE LINK, not beside it. The picture and the name are one person, so they should be one hover target and one tab stop; a sibling would give a keyboard user two stops that go to the same page. It carries alt="" for the same reason -- the name is right there in the same link, so a described image would have a screen reader announce the person twice. It is opt-in because a face is not always the useful thing. The related- posts strip does not take it -- see `compact` in post-card.html: at ~178px the byline is already collapsing to "12 authors". THE ARTICLE PAGE TAKES IT, and takes it whole -- pile included -- so the byline under a post title is the SAME element as the byline on that post's card, not a variant of it. An earlier attempt suppressed the pile there, reasoning that a full-width header has room for every name; that made the two places differ for a reason no reader can see, which is worse than either choice on its own. Keeping the pile there did need the metadata fixed. posts/single.html is the one caller passing `pagefindMeta`, and the collapsed form's visible text is "2 authors" -- which would otherwise become the author metadata of all 161 co-authored posts in site search. So the pile branch stamps the names EXPLICITLY (`author:`) instead of letting Pagefind read them off the element. What the eye gets and what the index gets may differ here; what the index gets must still be the authors. An author's OWN page does take it, which is worth saying because the opposite looks right at first: every card there is by the same person, so the portrait beside each one repeats what the profile at the top already shows. It earns its place on the co-authored posts, where the pile is the only thing on the page that says who else was involved. `pagefindMeta` IS OPT-IN, and must stay opt-in -- the same shape as sponsor-logo.html / board-logo.html's `pagefindImage`, and for the same reason. Pagefind takes the LAST element carrying a given meta key on a page, and this partial renders on every post card too: on `/today/` that is ten cards inside data-pagefind-body, so stamping the attribute here unconditionally would give the archive listing the byline of whichever post sorted last. THE THRESHOLD IS TWO, NOT THREE, AND IT IS MEASURED RATHER THAN GUESSED. In a 379px card, two faces with both names needs 428px and wraps the view count onto a second line; piling the faces first still needs 408px. The count form needs 265px.
