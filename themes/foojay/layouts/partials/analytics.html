{{/* The two third-party scripts foojay.io runs: Google Analytics 4 and Ketch, the consent manager. Both are OFF unless configured. THEY ARE LOADED DIRECTLY, NOT THROUGH A TAG MANAGER, and that is a deliberate break from what WordPress did (one GTM container, `GTM-M6ZT5NW`, carrying two retired Universal Analytics tags that resolved to this same GA4 property server-side, plus a Custom HTML tag booting Ketch). The container is 360 KB of JavaScript to deliver eleven lines, pointing at it would load Ketch twice and fire the dead UA tags, and a tag manager puts half the site's third-party behaviour in a web console where no PR can see it. Everything a reader's browser is asked to run should be readable here. A tag manager, if ever wanted, REPLACES this partial rather than joining it. Two rules, both derived rather than configured: 1. NOTHING RENDERS UNLESS IT IS CONFIGURED. No `ga` -> no gtag.js; no Ketch `org`/`property` -> no consent manager. Same posture as views-beacon.html: a local build, a fork or a contributor's `hugo server` never reports a pageview into foojay's property and never shows a consent banner. 2. CONSENT MODE IS EMITTED ONLY WHEN KETCH IS. Consent Mode defaults everything to `denied` and lets the consent manager grant what the reader agrees to, which is correct exactly when something is going to send the update. With no consent manager nothing could ever grant it, so a default-deny would silently reduce GA to permanent modelling. Hence it follows Ketch rather than being its own knob. `wait_for_update` gives Ketch 500ms to answer. Ketch's own Consent Mode integration is configured per property on the Ketch side, not here. If GA reports every session as consent-denied, that plugin is the first thing to check -- the defaults below are doing their job and nothing is updating them. The stub-then-boot shape of the Ketch snippet is Ketch's own: calls made before boot.js arrives queue on `window.semaphore` instead of being lost. Its published `?property=` override is left out on purpose -- a QA hook for switching properties on a live page, and this site has one property. */}} {{- /* Hugo lowercases every config key, so these lookups are all lowercase -- an `[params.analytics.ketch] Org` would register as `org` and a lookup for "Org" would find nothing, with no error. `index` rather than `.analytics.ga` so an unconfigured site is an absent key and not a nil dereference at build time. */ -}} {{- $cfg := index site.Params "analytics" | default dict -}} {{- $ga := index $cfg "ga" -}} {{- $ketch := index $cfg "ketch" | default dict -}} {{- $org := index $ketch "org" -}} {{- $property := index $ketch "property" -}} {{- $hasKetch := and $org $property -}} {{- with $ga }} {{- end }} {{- if $hasKetch }} {{- end }} {{- with $ga }} {{- end }}
