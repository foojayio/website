{{- /* A post's card thumbnail, and the single definition of what a card shows when the post has no usable image -- so a grid never has a hole. Params: page (required), eager (true for an above-the-fold LCP image). Three cases, ONE box: 1. an image that loads -> the image 2. no `image:` at all -> a derived placeholder tile 3. an image that FAILS -> the same tile, because the is painted on top of it and removes itself in onerror. Case 3 is common: dozens of posts hotlink their hero to a third-party host and some are already 404/403. A hotlink can die at any time and no build step can notice, so the fallback has to be in the browser. The tile is DERIVED, never authored: the label is the post's first category and the hue is hashed from it (`hash.FNV32a`, the same trick /calendar/ uses for a JUG's dot), so a category colours itself and there is nothing to store. search/single.html reproduces the same tile from the same two inputs, so a post looks the same in a grid and in a result list. */ -}} {{- $p := .page -}} {{- $eager := .eager | default false -}} {{- $label := "" -}} {{- with $p.Params.categories }}{{ $label = partialCached "category-name.html" (index . 0) (index . 0) }}{{ end -}} {{- if not $label }}{{ $label = site.Title }}{{ end -}} {{- /* Hashed from the LOWERCASED label, so the display-name lookup above cannot shift a tile's colour: lower("NoSQL") == lower("nosql"). Hash the raw label instead and every tile changes hue. */ -}} {{- $hue := mod (hash.FNV32a (lower $label)) 360 -}} {{ $label }} {{- with $p.Params.image }} {{- end }}
