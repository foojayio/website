{{- /* The key a page's read count is stored under, or "" if it isn't counted. ONE DEFINITION, called by everything that touches a count: views.html, views-total.html, views-beacon.html, baseof.html and comments-term.html. A hand-built key that disagreed would show up as a count silently stuck at zero, not as an error. `$counted` below is MIRRORED in layouts/index.stats.json, which reports views per section and has no page to ask. Add a section to one list and it must go in the other, or /stats.json reports it as zero. `
/`, never a bare slug and never a pathname: - The SLUG half is derived from the bundle folder or file name, so there is nothing for an author to write. A PATHNAME is the tempting alternative and a trap: the key is permanent, a URL is not, so every count would reset the next time a URL moved. Same shape as a giscus comment term for the same reason. - The SECTION half keeps the counted sections from colliding. They do not today, but that is luck: nothing stops a pedia entry and an author page wanting the same key, and the counter is a permanent store where a collision silently merges two pages' numbers. Add a section here to start counting it -- the Worker accepts any `
/` key. */ -}} {{- $counted := slice "posts" "pages" "pedia" "authors" -}} {{- $key := "" -}} {{/* NOT `.IsPage`: author profiles are BRANCH bundles, so that test silently stops matching them and every author's count reverts to nothing recorded. What matters is that the page has a FILE, so the slug can be derived, and that it is not a section LISTING. A profile is identified the way it is everywhere else: `type: "author"`. */}} {{- $isProfile := eq .Type "author" -}} {{- if and .File (in $counted .Section) (or .IsPage $isProfile) -}} {{- $key = printf "%s/%s" .Section (or .Params.slug .File.ContentBaseName) -}} {{- end -}} {{- return $key -}}
