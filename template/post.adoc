== A section heading

Sections start at `==`. Sub-sections use `===`. They become the "On this page"
navigation automatically.

Inline markup: *bold*, _italic_, `monospace`, and a
https://foojay.io[link with its text in brackets].

* A bullet
* Another one
** Nested, with two stars

. A numbered item
. The next one

== Code

A source block is a `[source,<language>]` line followed by a `----` fence. It is
syntax-highlighted by the same highlighter Markdown articles use, so the
language names are the same ones -- `java`, `bash`, `yaml`, `xml`, `kotlin`,
`json`, `python`, `sql` and so on. An unknown one renders unhighlighted rather
than broken.

[source,java]
----
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, foojay!");
    }
}
----

A `----` fence with no `[source]` line gives plain, unhighlighted output.

=== Block titles

Any block takes a caption: a line starting with a dot, directly above it.

.What the build does
[source,bash]
----
./gradlew build
----

=== Callouts

Numbered markers in the code, explained underneath. Markdown has no equivalent.

[source,java]
----
var list = new ArrayList<String>();   // <1>
list.add("foojay");                   // <2>
----
<1> Create the list.
<2> Add to it.

== Admonitions

The labelled boxes that set a remark apart from the text around it. One word,
then a colon:

NOTE: Something worth knowing.

TIP: A shortcut the reader may not know.

IMPORTANT: Something they should not skip.

WARNING: Something that will bite them.

CAUTION: Something that could lose data.

== Tables

`cols` sets the relative column widths; `options="header"` makes the first row
a header. A `2+|` prefix spans two columns and `.2+|` spans two rows.

.An optional caption
[cols="1,2", options="header"]
|===
| Column | What goes in it

| First | Something short
| Second | Something longer, which is why this column is twice as wide
|===

== Images

Put the file in THIS folder and reference it by name. The text in the brackets
is the DESCRIPTION, and it is the only part of an image a reader using a screen
reader gets -- write what it shows, the way you would say it out loud. Leave it
empty only when the image is decoration; the PR check reports empty ones so you
can confirm that was deliberate, and never fails your pull request over it.

image::my-image.png[The Ports view in IntelliJ, showing the app on port 8080]

Every image in an article is click-to-enlarge automatically.

Foojay's own shortcodes work here too, for a floated or captioned image and for
a gallery -- see template/post.md for what each one takes:

{{< img src="my-image.png" alt="The Ports view in IntelliJ" class="alignright" width="320" caption="An optional caption" >}}

== One thing that is Markdown-only

Nothing else differs, but this does: Mermaid diagrams work in AsciiDoc as well,
written as a `mermaid` source block.

----
graph LR
    A[Source] --> B[javac]
    B --> C[Bytecode]
